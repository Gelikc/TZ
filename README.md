# MAX — чат на React + GREEN-API

Минимальный клиент: подключение по `idInstance` и `apiTokenInstance`, создание личного чата по номеру, отправка и получение текста. Интерфейс вдохновлён веб-версией MAX: светлая палитра, список диалогов, отдельная область переписки, адаптация для телефона.

## Запуск

Нужен Node.js 22.12+.

```bash
npm install
npm run dev
```

Откройте адрес, который Vite выведет в терминале (обычно http://127.0.0.1:5173).

```bash
npm test        # проверка API, очереди и пользовательского сценария с mock-ответами
npm run build  # production-сборка в dist/
npm run preview
```

## Подготовка GREEN-API

1. Создайте **инстанс MAX** в https://console.green-api.com/ и авторизуйте его. Статус должен быть `authorized`.
2. В настройках инстанса установите `incomingWebhook: "yes"`, очистите `webhookUrl`. При необходимости включите `outgoingWebhook: "yes"` для статусов исходящих сообщений. После изменения подождите около минуты.
3. Скопируйте `idInstance`, `apiTokenInstance`, `apiUrl` из кабинета.
4. Введите ID и токен на странице входа. В разделе «Адрес сервера API» укажите **apiUrl именно вашего инстанса**. По умолчанию указан `https://3100.api.green-api.com`; у других инстансов сервер может отличаться.
5. Нажмите «Войти в чат», затем «Новый чат». Введите номер РФ (+7) или Беларуси (+375). Номер 8… для РФ преобразуется в 7….
6. Напишите сообщение. Ответ из MAX появится автоматически. Enter отправляет, Shift+Enter добавляет строку.

## Реализация

- `src/api.js`: запросы, ограничение адреса сервера доменом GREEN-API, таймауты, последовательный long polling и повтор подключения с задержкой.
- `src/messages.js`: фильтрация текстовых уведомлений, маршрутизация по MAX chatId, устранение дублей по idMessage.
- `src/App.jsx`: вход, список чатов, поиск, модальное окно нового чата, переписка и выход.
- `src/styles.css`: адаптивный интерфейс.

Перед входом проверяются `GetStateInstance` и `GetSettings`. `CheckAccount` получает внутренний `chatId` по телефону, поэтому ответ собеседника попадает в тот же диалог. `SendMessage` отправляет `{ chatId, message }`. Максимум — 4000 символов. Подтверждение API означает постановку в очередь, а не доставку: интерфейс показывает «В очереди».

`ReceiveNotification` вызывается с `receiveTimeout=25`. После обработки вызывается `DeleteNotification`. Не относящиеся к тексту уведомления также подтверждаются, чтобы не блокировать очередь. Приложение рассчитано на отдельный инстанс с одним потребителем уведомлений: не запускайте для него параллельно другой клиент/бот или вторую вкладку с получением.

## Хранение и ограничения

Учётные данные, чаты и сообщения находятся только в памяти вкладки. После перезагрузки или выхода история очищается; подтверждённые уведомления повторно не загружаются. Исторические сообщения, вложения, групповые чаты и синхронизация исходящих из мобильного приложения не входят в эту реализацию. Открытая вкладка получает новые личные текстовые сообщения, включая текст с URL. Черновики сохраняются при переключении чатов до выхода.

Запросы идут напрямую из браузера в GREEN-API по HTTPS. Токены не сохраняются в localStorage/sessionStorage и не выводятся приложением в консоль. Как у любого браузерного клиента, токен доступен владельцу вкладки через инструменты разработчика. Для публикации разместите `dist/` на HTTPS-хостинге. При ограничениях CORS со стороны API понадобится собственный серверный прокси.

Живой обмен требует действующих учётных данных и второго пользователя MAX. Автотесты используют подменённые ответы; реальный обмен без этих данных не проверен.
